# Build Order

## Stage 0 — Repository Audit
- inspect current repository
- identify framework/version/package manager
- inspect lint/typecheck/test/build commands
- inspect existing components/styles/content
- note conflicts with this specification
- do not edit until audit is complete

## Stage 1 — Portfolio Foundation
- app shell
- strict TypeScript
- design tokens
- fonts
- layout/container primitives
- header
- footer
- global metadata baseline

Validate.

## Stage 2 — Homepage
- hero
- selected work
- AI evaluation section
- expertise
- private professional work
- about preview
- contact

Use honest `In Development` project states when real visuals/links are not yet available.

Validate responsive layouts.

## Stage 3 — Content Architecture
- centralized project metadata
- work index
- dynamic project route system
- MDX/local structured case-study content
- next-project navigation

Validate.

## Stage 4 — About / Work Refinement
- full About page
- Work archive
- secondary-project representation

Validate.

## Stage 5 — Accessibility / SEO / Performance
- sitemap
- robots
- social metadata
- JSON-LD only where accurate
- focus/reduced-motion/keyboard improvements
- image optimization

Validate.

## Stage 6 — EvalForge
Build V1 in its own repository according to the project spec.

## Stage 7 — EvalForge Portfolio Integration
- capture screenshots
- create architecture visual
- finish case study
- add real GitHub/demo links
- change status only when factual

## Stage 8 — AgentScope
Implement, validate, document, integrate.

## Stage 9 — EstateAI
Implement, validate, document, integrate.

## Stage 10 — LaunchKit AI
Implement, validate, document, integrate.

## Stage 11 — GitHub Profile Polish
- concise profile README
- pin strongest repositories
- ensure READMEs/CI/issues/releases are credible

## Stage 12 — Launch Audit
Run all portfolio acceptance criteria and remove stale placeholders.
