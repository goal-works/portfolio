# Codex Execution Instructions

## Behavioral Rules
1. Read all relevant specification files before implementation.
2. Inspect the repository before modifying it.
3. Preserve existing user work.
4. Implement incrementally.
5. Use existing project conventions when sound.
6. Prefer straightforward architecture over impressive-looking complexity.
7. Do not invent personal or professional facts.
8. Do not silently rewrite approved copy.
9. Do not present planned functionality as completed.
10. Run validation after every major phase.

## Dependency Policy
Before adding a dependency, determine:
- whether the framework/platform already solves the problem,
- whether the dependency is maintained,
- whether it materially reduces complexity.

Avoid dependency inflation.

## Git Practices
When commits are requested/appropriate, use meaningful messages such as:
- `feat: add editorial project case-study layout`
- `feat: implement asynchronous benchmark execution`
- `fix: prevent duplicate task execution`
- `test: cover pass@k aggregation`
- `docs: document evaluator architecture`

Do not manufacture fake historical commits or dates.

## Copy Integrity
Do not invent:
- employers
- clients
- testimonials
- exact years
- metrics
- project performance
- user counts
- revenue
- certifications

Unknown contact/social URLs should remain configurable placeholders or be omitted.

## Design Integrity
Do not introduce:
- random bright colors
- giant gradients
- glass cards everywhere
- skill meters
- particle backgrounds
- excessive animations
- inconsistent radii
- unrelated iconography

## Validation
Use the repository's actual commands and report exact results.
Never claim tests/builds passed if they were not executed.

## Escalation
Use reasonable engineering judgment for ordinary implementation details.
Do not guess when ambiguity concerns:
- personal facts
- professional claims
- destructive operations
- credentials/secrets
- security boundaries
- major architecture changes that contradict the specs

## Final Report Format
### Completed
### Changed
### Validation
### Not validated
### Remaining
### Risks / decisions
