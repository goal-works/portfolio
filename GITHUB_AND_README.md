## Flagship README Structure
1. Project name + one-sentence description
2. Large real product screenshot
3. Overview
4. Why this exists
5. Key capabilities
6. Architecture
7. Quick start
8. Configuration
9. Development
10. Testing
11. Project structure
12. Technical decisions/tradeoffs
13. Roadmap
14. Contributing
15. License

## Useful Badges Only
- CI
- License
- relevant runtime version
Avoid vanity badge walls.

## Documentation
Suggested:
```text
docs/
├── architecture.md
├── development.md
├── deployment.md
├── testing.md
└── decisions/
```

Use lightweight ADRs for meaningful architecture decisions.

## Issues
Use genuine issues for actual work. Do not create fake activity for appearance.

## Releases
Use releases that correspond to real milestones, e.g. v0.1 initial workflow, v0.2 observability, v1.0 stable portfolio-ready release.
